# 119파이어 개인용 완전자동 업무비서 V2

`com.fire119.assistant` · Android 8.0 이상 · 개인용 local-first 업무비서

## V2에서 실제로 저장·연결되는 흐름

전화녹음 폴더 → `CallRecord` 대기열 → 전사/AI 분석 → 고객·문의 후보 → 할 일/일정 후보 → 현장 → 사진/작업기록 → 견적/견적항목 → 수금·자료 → 블로그 초안·백업 대기열

모든 핵심 업무 기록은 Android **Room 로컬 DB**에 먼저 저장됩니다. 고객 전화번호, 현장, 문의, 할 일, 통화, 사진, 견적, 견적항목, 수금, 문서, 블로그 초안, AI 분석과 자동화 작업 상태를 별도 테이블로 보관합니다.

## 구현된 주요 기능

- 빨강·흰색 119파이어 V2 홈: 오늘 업무, 우선순위, 새 통화 분석, 수금 확인
- 문의 등록 시 전화번호 기반 고객 연결, 현장·후속 할 일 연결
- 현장별 사진 촬영·로컬 저장과 Room 사진 기록
- 현장 음성 메모(STT)와 “끝났어” 완료 후보/수금 확인 Task
- 견적 항목 수량×저장 단가 계산, 부가세, 견적 초안, PDF 생성
- 삼성 기본 통화녹음 폴더 SAF 연결, 중복 없는 파일 기록, WorkManager 주기 확인, AI 분석 대기열
- OpenAI 전사·Responses API를 **Netlify 서버를 경유**해 사용. API Key는 앱에 포함하지 않음
- 음성 질문(STT), 앱 화면 답변, 선택적 TTS
- `오늘 거 알아서 정리해`, `지금 뭐부터 해야 돼?` 규칙 기반 요약
- `119파이어 스토리텔링 SEO 21.0` 별도 서버 설정과 신규 블로그 초안 API

## 최초 1회 설정

1. 앱 설정 → 통화녹음 폴더 연결에서 갤럭시 기본 통화녹음 폴더를 선택합니다.
2. Netlify에 `server/`를 배포하고 환경변수를 설정합니다.
   - `OPENAI_API_KEY`
   - `APP_ACCESS_CODE`
   - 선택: `OPENAI_MODEL` (기본 `gpt-5`), `TRANSCRIBE_MODEL` (기본 `gpt-4o-mini-transcribe`)
3. 앱 설정 → AI 서버 연결에 Netlify 주소와 `APP_ACCESS_CODE`만 입력합니다.

OpenAI API Key·Google 비밀번호·Drive 비밀번호를 APK에 입력하거나 저장하지 않습니다.

## SEO 21.0 블로그 초안

`server/config/seo21.rules.json`이 현재 적용 규칙입니다. 이 파일을 바꾸면 이후 기준(SEO 22.0 등)으로 교체할 수 있습니다.

초안은 실제 현장 자료만 입력으로 받으며, 실제로 확인하지 않은 원인·작업·시험·결과·금액은 `확인 필요`로 남기도록 서버 지침을 둡니다. 기존 상위 노출 글을 자동 수정하지 않습니다.

## Android/Google 정책상 한계

- 앱은 통화를 직접 녹음하지 않습니다. 사용자가 연결한 삼성 기본 통화녹음 폴더만 읽습니다.
- Android SAF 폴더는 파일 변경을 완전 실시간으로 감시하기 어렵습니다. WorkManager의 약 15분 주기 확인(정확한 실행 시각 보장 없음)과 앱의 “지금 확인”을 함께 사용합니다.
- 통화 전사 업로드는 인터넷과 Netlify 설정이 있어야 하며, 실패한 기록은 로컬 대기 상태로 남습니다.
- Calendar/Google Drive 실제 동기화는 Google OAuth Client 설정과 사용자의 최초 승인이 필요합니다. 현재 V2는 중복 방지 일정 후보와 local-first 백업 구조를 준비하며, 승인 전에는 외부 캘린더·Drive에 전송하지 않습니다.
- 실제 문자 발송, 견적 최종발송, 계약 상태 확정, 삭제·외부공유는 자동 실행하지 않습니다.

## APK 빌드

GitHub Actions의 **Build 119Fire APK**가 `main`과 `v2` 푸시에서 `app-debug.apk`를 생성합니다.

GitHub → Actions → 성공한 실행 → Artifacts → `119fire-hybrid-apk`에서 받습니다.
